# Internationalization (i18n) guide

The user interface source language is **English**. All user-visible
strings must be wrapped with `self.tr()` (widgets) or
`QApplication.translate("MainWindow", ...)` (outside widgets), so they can
be extracted by Qt Linguist later.

Spanish and other translations will be created **at the end of the
project**, when the UI is stable (per maintainer decision, 2026-08-31).

## Current state

- **ui.py**: all user-visible strings are English, wrapped with `self.tr()`
  (context: `Teleprompter`).
- **main.py**: dialog strings use
  `QApplication.translate("MainWindow", ...)` (context: `MainWindow`).
- **templates/remote.html**: web remote page is in English. When the Qt
  translations exist, this page should receive a `?lang=es` variant or a
  small JS dictionary.
- Log messages are English and are **not** translated (developer-facing).

## Workflow for adding a translation (e.g. Spanish)

### 1. Extract the strings

`pylupdate6` is already available on the reference machine (Debian 13,
`/usr/bin/pylupdate6`).

```bash
mkdir -p translations
pylupdate6 ui.py main.py -ts translations/teleprompter_es.ts
```

### 2. Translate with Qt Linguist

```bash
linguist translations/teleprompter_es.ts
```

Qt Linguist comes with the Qt 6 tools (check the exact package with
`apt-cache search linguist`; on this machine `lupdate` is already
present as `/usr/bin/lupdate`).

### 3. Compile and install

```bash
lrelease translations/teleprompter_es.ts -qm translations/teleprompter_es.qm
```

The application automatically loads any `teleprompter_<locale>.qm` and
`qt_<locale>.qm` files from the `translations/` directory next to the
program (see `install_translators()` in `main.py`), matching the system
locale (`es_ES` preferred, then `es`).

### 4. Test

```bash
LC_ALL=es_ES.UTF-8 python3 main.py
```

## Rules for developers

1. Never hardcode user-visible text without `tr()` / `translate()`.
2. Keep English source strings; translations are external `.ts`/`.qm`
   files, never in-code conditionals.
3. Do not concatenate translated fragments at runtime; use
   placeholders (`self.tr("Error: {0}").format(e)`) so translators see
   whole sentences.
4. Plural forms: use the three-argument `tr("%n file(s)", "", n)`.
5. When adding new strings, regenerate the `.ts` files so translators
   see the additions (`pylupdate6` merges without losing old work).
6. The `.ts` files are the source of translation work and belong in the
   repository; `.qm` files are build artifacts (also committed here for
   now, since there is no packaging step yet).
